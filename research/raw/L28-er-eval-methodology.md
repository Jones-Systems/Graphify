**Verdict:** Top pick = build exclusively on Splink 4's own evaluation stack (already pinned, MIT, DuckDB/CPU): `accuracy_analysis_from_labels_table` + blind `labelling_tool_for_specific_record` + band-stratified sampling. One-time cost ≈ 500 blind pair reviews (~±3–5pp precision CI) buys a reusable frozen adjudication set that turns every future config/threshold change into a measurable promote/reject decision.
Integration sketch: `uv run er_eval sample --bands 0.5:0.7,0.7:0.9,0.9:1.0 --n 150 --seed 42` → HTML blind reviews → labels.parquet → `er_eval gate --candidate cfg.json --incumbent prod.json` emits gate_report.json (Wilson-LB P, ΔR, ΔF1 CI, plateau, blocking PC/RR) consumed by existing promotion pipeline.

## Gate pass rules (defaults)
- P_lb(t*) = Wilson95 lower bound of band-weighted precision ≥ 0.99 (auto-merge tier) and ≥ incumbent point estimate − 0.002.
- ΔF1(candidate−incumbent) on SAME frozen labels: paired cluster-bootstrap 90% CI lower bound > −0.005; labelled-recall point drop ≤ 1pp.
- Plateau: every metric moves <0.5pp across t*±0.02; |E(t)| edge-count drift <2%.
- Blocking edits: cumulative comparisons within budget (RR), no band loses >1% edges, n_largest_blocks shows no new skew block >0.1% of comparisons.
- All artifacts (dashboards HTML, truth table CSV, model JSON, labels hash) attached to the PR; gate is deterministic given seed+labels hash.

## Sample-size cheat sheet (95%, worst-case p=0.5)
±10pp→97 · ±5pp→385 · ±3pp→1068 · ±2pp→2401; high-precision regime p≈0.98: ±1pp→752 · ±0.5pp→3012; observed 0 errors in n ⇒ Wilson95 UCL≈3/n (n=385→≤1%). Apply FPC when pair pool bounded. Review effort scales linearly; start 150/band ×3 bands +100 below-threshold (recall side).

Env fit: everything above is pip-installable MIT/BSD/Apache, runs on 16 CPU cores, peak RAM « 3 GiB (sampled review avoids materializing full pair space beyond candidate table), zero cloud dependencies.
