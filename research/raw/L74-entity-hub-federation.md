  "architecture": "# LANE L70 — T11 Federation: Shared Entity-Hub Corpus Design\n\n*Research date: 2026-08-25. All versions/licenses verified against primary sources (PyPI JSON API, official docs/repos) on this date. Environment: Debian VPS, 16 CPU cores, NO GPU, MemAvailable hard floor ≥ 3072 MiB, Python 3.13, offline/self-hostable preferred.*\n\n## 0. Scope and role of the hub\n\nA dedicated **entity hub** (`people/orgs/projects` corpus) acts as a canonical reference corpus that all 18 VPS repos link into. Each repo keeps its own documents/graphs; the hub holds **one canonical record per real-world entity**, plus **typed links** `(hub_entity ↔ repo-local id)` with provenance and confidence. Corpora never import each other's entity tables directly — they resolve through the hub, which kills duplicate-entity drift across repos and gives PPR-over-KG fusion a single bridging subgraph.\n\nDesign stance: this is deliberately a **boring architecture** — one SQLite file + append-only change feed + existing stack components (Splink/GLiNER/RapidFuzz/tantivy/sqlite-vec already licensed and deployed). No new services by default.\n\n---\n\n## 1. Schema\n\nBorrow the **FollowTheMoney** ontology (MIT, v4.10.2, Python ≥3.11 — runs on 3.13) as vocabulary: schemata `Person`, `Organization`, `Company`, `PublicBody`, `Project` (or map project → `Event`/custom `Project` extension; FtM supports custom schemata), relationships as **interstitial entities** (`Directorship`, `Ownership`, `Membership`, `Employment`) so relations themselves carry properties/provenance. Borrow its **statement-based data model**: the atomic unit is a claim about a property value, not the entity — this makes provenance, temporal validity, and conflict-free merges first-class.\n\nConcrete SQLite sketch (WAL mode, single writer, read-only replicas via `ATTACH ... READ_ONLY`):\n\n```sql\n-- canonical entities; UUIDv5 (namespace constant + kind + slug), never reused\nCREATE TABLE entities (\n  id TEXT PRIMARY KEY,             -- uuidv5, stable across merges via redirects\n  kind TEXT NOT NULL CHECK (kind IN ('person','organization','company','publicbody','project')),\n  preferred_name TEXT NOT NULL,\n  created_at TEXT NOT NULL, updated_at TEXT NOT NULL,\n  deleted_at TEXT,                 -- tombstone; rows are never hard-deleted\n  schema_version INTEGER NOT NULL\n);\n-- claim-level facts (FtM 'statements' pattern)\nCREATE TABLE claims (\n  stmt_id INTEGER PRIMARY KEY,\n  entity_id TEXT NOT NULL REFERENCES entities(id),\n  prop TEXT NOT NULL,              -- e.g. name, birthDate, registrationNumber\n  value TEXT NOT NULL, original_value TEXT, lang TEXT,\n  rank TEXT NOT NULL DEFAULT 'normal',   -- preferred|normal|deprecated (Wikidata ranks)\n  source_corpus TEXT NOT NULL, source_id TEXT,\n  method TEXT NOT NULL,            -- gliner|splink|manual|import\n  confidence REAL, observed_at TEXT NOT NULL,\n  first_seen TEXT NOT NULL, last_seen TEXT NOT NULL,\n  external INTEGER DEFAULT 0       -- 1 = pending human review (nomenklatura pattern)\n);\nCREATE TABLE aliases (            -- feeds RapidFuzz dedupe + tantivy alias index\n  entity_id TEXT NOT NULL, value_norm TEXT NOT NULL, value_raw TEXT NOT NULL,\n  source_corpus TEXT, PRIMARY KEY (entity_id, value_norm, source_corpus)\n);\nCREATE TABLE links (              -- the federation edge set; corpora own their half\n  hub_entity_id TEXT NOT NULL, corpus_id TEXT NOT NULL, local_id TEXT NOT NULL,\n  rel TEXT NOT NULL,               -- mentions|about|authored|owns|member_of ...\n  confidence REAL NOT NULL, method TEXT NOT NULL,\n  status TEXT NOT NULL DEFAULT 'active',  -- active|dangling|rejected\n  first_seen TEXT NOT NULL, last_confirmed TEXT NOT NULL,\n  PRIMARY KEY (hub_entity_id, corpus_id, local_id)\n);\nCREATE TABLE merges (             -- merge/split audit + redirect chain\n  survivor_id TEXT NOT NULL, merged_away_id TEXT UNIQUE NOT NULL,\n  reason TEXT, actor TEXT, ts TEXT NOT NULL\n);\nCREATE TABLE cursors (            -- per-consumer sync position\n  consumer TEXT PRIMARY KEY, last_seq INTEGER NOT NULL\n);\n-- indexes: aliases(value_norm); claims(entity_id,prop); links(corpus_id,local_id);\n--          links(hub_entity_id,status); claims(external) WHERE external=1\n```\n\nKey decisions:\n- **IDs are immutable; identity changes are events.** Merges write a `merges` row and keep the loser as redirect (Wikidata practice). Never re-key; never reuse IDs after erasure.\n- **Additive-only schema evolution**; `schema_version` negotiated by readers; unknown props preserved verbatim.\n- **Names are claims, not columns**: every name variant stays as an alias + claim so fuzzy matchers see history.\n\n## 2. Update protocol\n\nPattern: **transactional outbox + monotonic sequence + consumer cursors** (idempotent upserts keyed by natural keys; at-least-once delivery, exactly-once effect).\n\n1. **Extract** (per repo): GLiNER surfaces mentions; RapidFuzz normalizes; candidate link events `(corpus_id, local_id, name, context)` are appended to that repo's outbox table in the same transaction as the source write.\n2. **Propose**: hub ingester drains outboxes (polling, seq-cursor per corpus; HTTP pull or filesystem drop both work offline). New candidates land as `external=1` claims/links — **never auto-applied**.\n3. **Resolve**: Splink 4 (`SQLiteAPI`, Fellegi–Sunter m/u probabilities) blocks on normalized-name + DOB/geo/registration keys, scores pairs; threshold bands: auto-link ≥ high band into existing entity only (link to *existing*, never transitively chain), middle band → human review queue (`external=1`), below → discard with stats.\n4. **Commit**: accepted claims get `canonical_id`; entity `updated_at` bumps; a delta record `{seq, op, entity_id}` appends to the hub log. Deletes = tombstones broadcast the same way (this doubles as GDPR-erasure propagation for the people corpus).\n5. **Consume**: repos advance cursors, rebuild affected local indexes (tantivy alias entries, sqlite-vec entity vectors, graphifyy bridge-node stubs) incrementally.\n6. **Reconcile**: nightly dangling-link sweep (target gone → `status=dangling`, TTL → reject); weekly re-validation sample of oldest confirmed links; quarterly tagged snapshot export (immutable release consumers can pin).\n\nFailure containment: ingest is idempotent on `(source_corpus, source_id, prop, value_hash)`; replays are safe; a noisy spoke can only degrade its own links' confidence weighting, not mutate others' claims (per-source weights on claims).\n\n## 3. How PPR treats hub nodes\n\nMechanics: in PPR-over-KG fusion, `π_q = α·p_q + (1−α)·Pᵀπ_q` (teleport on query seeds `p_q`). Probability concentrates on nodes **structurally near seeds weighted by connectivity**, so high-degree nodes absorb mass from many paths regardless of semantic relevance — personalization removes *global* popularity bias but not *local* hub bias (Haveliwala 2002; GraftNet/Sun et al. 2018). Federation makes this worse: wiring every corpus through the hub multiplies hub node degree super-linearly, creating a rich-get-richer loop where generic orgs/people dominate every fused ranking.\n\nMitigations (cheap on scipy sparse CSR; hub graphs of 10⁴–10⁶ nodes fit well under the 3 GiB floor):\n1. **Degree-damped transition weights**: `w(u→v) ∝ 1/log(1+d(v))^β`, β≈0.5–1 — caps mass flow into hubs.\n2. **Contrastive/global-prior correction**: score `log π_q(v) − λ·log PR(v)` (ratio-to-global-PageRank or subtract a uniform-seed baseline PPR) — surfaces nodes *unusually* close to this query's seeds, not merely important everywhere. One extra power iteration per epoch; negligible cost.\n3. **Relation-aware edges** (GraftNet): up-weight relation types matching query intent (bge-reranker-base scores relation labels); cap expansion per generic relation type.\n4. **Anchor-concentrated teleport + early truncation** (fewer effective hops shrinks hub reach).\n5. **Post-hoc hub penalty** `π_q(v)/(d(v)+ε)^γ` at fusion time before the gated 3-way RRF, so RRF sees calibrated scores.\n6. **Diversity quota / MMR** in final selection to stop one hub's neighborhood monopolizing top-k.\n7. **Structural choice**: keep hub graph **separate and join at fusion time** (bridge-stub nodes), don't materialize hub edges into each repo's structural graph — bounds per-repo degree inflation and keeps graphifyy==0.9.16 outputs stable.\n\n## 4. Failure modes of hub-and-spoke designs (and countermeasures)\n\n| Failure mode | Mechanism | Countermeasure |\n|---|---|---|\n| Availability coupling / SPOF | Hub down ⇒ cross-repo resolution down | Read-only replicas; never transitive auto-chaining; unmerge support via `merges` audit |\n| ID churn on split/merge | Downstream caches key dead ids | Redirect table; IDs never reused; cursor-aware invalidation |\n| PPR centrality inflation | Federated hub inflates hub scores globally | §3 mitigations (damping, contrastive prior) |\n| Stale/dangling spokes | Source records deleted, links rot | Nightly sweep, TTL rejection, `last_confirmed` freshness weighting |\n| Write contention / thundering herd | 18 repos push simultaneously | Per-corpus cursors, batching, debounced reindex;
