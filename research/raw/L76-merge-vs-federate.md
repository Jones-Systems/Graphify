## Contamination cases (why merged corpora get poisoned)
- **C1 Domain-shift vector pollution** [H]: one shared embedding space mixes incompatible distributions; BEIR shows dense retrievers lose catastrophically outside their training distribution (DPR BioASQ 0.127 vs 0.465 BM25). In a merged 18-repo index, every query pays for domains unlike its target.
- **C2 Entity/identifier collisions** [M for graphs, INFERENCE-L for code]: GraphRAG conflates entities sharing a title and has no fuzzy-resolution subsystem (dedup keyed on title+type; issue #1718). Across code repos, identical symbol names (`handler`, `config`, `Client`) collide the same way — merged lexical/vector indexes flood top-k with wrong-repo neighbors.
- **C3 Fork/near-duplicate canonical ambiguity** [INFERENCE-M]: stale forks and copied snippets outrank or fragment canonical sources once merged; requires a global MinHash-style dedup pass that a per-corpus design never needs.
- **C4 Access-control / license bleed-through** [H]: Milvus documents partition keys as non-security boundaries; Weaviate states tenant isolation is not a substitute for authorization; Elasticsearch moves isolation into app-enforced filters — every merged store converts a structural guarantee into a per-query filter that one forgotten predicate turns into a leak.
- **C5 Rebuild blast radius & noisy neighbors** [H]: Elastic's index-per-tenant OOM shows shared-infrastructure coupling cuts both ways — a bad bulk import or heavy rebuild degrades ALL queries in a merged index; per-corpus indexes contain failures (Weaviate's stated noisy-neighbor rationale).
- **C6 Schema/filter sprawl** [H]: Qdrant flags payload-schema variability as its own reason to split; heterogeneous metadata across 18 repos makes shared-filter semantics conditional soup.

## Decision criteria: merged-global vs federated-per-corpus
**Hard blockers to merging — ANY one present ⇒ stay federated:**
- **B1 Vector-space incompatibility**: different embedders, dimensions, distance metrics, or preprocessing per corpus (a single ANN space is then meaningless without a full unified re-embed).
- **B2 Non-uniform ACL/license/privacy boundaries** (structural isolation beats per-query filtering — C4).
- **B3 Divergent update/rebuild cadence**: partial updates inside one HNSW graph break snapshot consistency; our deterministic-ID rolling rebuild REQUIRES independent per-corpus swap (B3 is currently active for us).
- **B4 Heterogeneous chunking/metadata schemas** preventing shared filter semantics.

**Lean federated signals:** S1 polysemy/identifier collisions across domains; S2 un-deduplicated forks/copies; S3 blast-radius isolation wanted; S4 query traffic is mostly single-corpus.

**Lean merge-global signals (all of B1–B4 clear AND):** M1 large share of queries legitimately span corpora (rule of thumb >~30%) — because routing error then dominates (router accuracy × per-corpus recall bounds end-to-end quality, per Arguello 2009 framing); M2 very many tiny corpora where per-index overhead dominates (Elastic fixed-cost evidence — irrelevant at our scale of 18); M3 single owner, uniform governance, synchronized reindex budget.

**Quantitative adoption gate (run before any merge):** build ~100-query probe set labeled with true target corpus(a); evaluate (a) merged-global nDCG@10 + within-corpus P@10, (b) routed-federated = router top-1 accuracy × per-corpus recall@k, (c) fan-out-all + RRF(k=60) nDCG@10. Adopt the config maximizing nDCG subject to ZERO cross-boundary leakage; re-run quarterly and after any embedder change. Low router confidence (embedding-distance margin or QPP proxy) must trigger the fan-out fallback, never a forced choice (LlamaIndex failure-mode evidence).

## Stack-fit note (16-core CPU, 3072 MiB floor)
18 small mmap'd per-corpus indexes permit a hot-resident working set with idle repos paged out (Weaviate INACTIVE-tenant offload is the same pattern); one merged index keeps the whole graph's pages hot. Per-corpus indexes also let us tune quantization/chunkers/rerankers independently (Qdrant lifecycle criterion).

## Verdict (≤3 lines)
Top pick: **federated-per-corpus by default** — one index per repo, thin STARTS-style meta-layer (size + centroid + top terms) for routing, RRF(k=60) fan-out fallback; vendors (Qdrant, Milvus, Weaviate, Elastic) converge on "merge only when space+ACL+lifecycle are uniform," and BEIR plus LlamaIndex evidence show merged-heterogeneous poisoning and uncalibrated routers respectively.
Why: B1–B3 are all presently true for the 18-repo fleet (different embedders/licenses, rolling deterministic-ID rebuild), while cross-corpus queries remain the minority.
Integration sketch: deterministic-ID per-repo index → atomic swap on rebuild → centroid/rules router with confidence gate → below-threshold queries hit all 18 and fuse via RRF → optional cross-encoder rerank of fused top-50 → merge any repo pair only after passing B1–B4 + probe-set nDCG win ≥5%.
