## Entity-typing fit for our repos (people/orgs/software/projects)
- **People**: Q5; precision via P106 (occupation closure e.g. programmer), P496 ORCID exact-match; GitHub-username property (P2037 — verify current coverage at integration) enables deterministic contributor anchoring from commit metadata.
- **Orgs**: Q43229 organization with P279* expansion (business/companies/vendor labs); anchor by homepage domain ↔ P856 and by P127 ownership chains — feeds org-level PPR nodes.
- **Software**: Q7397 (+library/language subclasses); strongest anchor is P1324 source-repo URL matched against our git remotes — zero-fuzzy, near-perfect precision; enrich with P277/P178 for stack-aware search facets.
- **Projects**: usually modeled as Q7397 instances; where missing, fall back to homepage/label matching with QRank prior. Type-constraint filtering (candidate must reach seed class via P31/P279*) is the single largest precision lever.

## License & freshness mechanics
- **Data**: Wikidata main/property/lexeme namespaces are CC0-1.0 (Wikidata:Licensing) → QIDs, labels, descriptions, claims freely redistributable; avoid ingesting Wikipedia article TEXT (CC BY-SA share-alike) into product artifacts.
- **Tooling licenses**: MIT (wdgrep, wdumper, KGTK, pywikibot, QRank code, REL), Apache-2.0 (WDTK, QLever, OpenTapioca), GPL-3.0 (wd2sql — internal use OK, review before external distribution), CC-BY-NC (mGENRE — blocked without owner approval).
- **Dump freshness**: nominally ~weekly, observably IRREGULAR (Feb-2025 corrupted latest-all; Jul-2025 truncated 4.9 GB dump, T399544). Always fetch `.sha1`, verify size plausibility (~90–160 GB) before processing. Recommended cadence: quarterly full re-carve + EventStreams-driven invalidation of anchored QIDs daily; live API only for misses.
- **API freshness/limits**: Action API always current; documented limits 10/min anonymous, 200/min compliant-UA (2026 docs); WDQS 60 s hard timeout, adaptive UA/IP-bucket throttling — batch seed jobs asynchronously, cache ≥5 min locally.

## Verdict
Top pick: **wdgrep-carved CC0 subset → QLever subset-index + QRank priors**, with pywikibot/Action-API (compliant UA ≤200 req/min) as the thin live fallback; skip KGTK/mGENRE/OpenTapioca. Why: only combo that is fully offline-capable, keyless, license-clean (CC0/MIT/Apache), and respects the 3 GiB RAM floor (full-Wikidata QLever and KGTK do NOT).
Integration sketch: quarterly `aria2c` dump → `pigz -dc | wdgrep --claim 'P31:Q5|P31:Q43229…|P31:Q7397'` + `build-graph P31,P279` closure pass → NDJSON into QLever (typed SPARQL candidate gen) and a tantivy labels/aliases index → anchoring = exact anchors (P1324/P856/P496) first, then BM25 label match reranked by QRank×type-constraint → emit QID nodes/edges into the existing PPR-over-KG fusion; EventStreams marks stale QIDs nightly.
