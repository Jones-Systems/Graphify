# LANE L77 — T11 Federation: Cross-Corpus Path-Finding UX
Routing heuristics for which corpus to search first when a question spans repos; classifier-lite approaches and escalation rules.
Environment: Debian VPS, 16 CPU cores, no GPU, MemAvailable floor 3072 MiB, Python 3.13, offline/self-hostable, permissive licenses. Evidence gathered 2026-08-25 via primary sources (GitHub releases, PyPI, HF model cards, arXiv, CMU IR papers).

## Design brief: routing signal stack + escalation ladder (proposed spec)
1. **Per-corpus score** S(C,q) = w3·gazetteer-hit-mass + w2·cos(q, corpus-centroid/route-utterances) + w1·z(BM25-probe-top-k) + w0.5·recency/activity prior. All signals computable in <5 ms CPU total; gazetteer = symbol/path/package term→doc-frequency tables built during the existing index pass (aligns with deterministic-ID rebuild). BM25 scores must be z-normalized per corpus — raw BM25 is not comparable across collections (federated-IR result-merging problem, CORI/ReDDE literature).
2. **Fan-out rule**: order corpora by S; if s1−s2 ≥ δ (start δ=0.12 on z-scores) search top corpus only; else run top-2 concurrently (16 cores allow). Calibrate δ with RouteLLM-style `calibrate_threshold` workflow against a target single-corpus rate and an nDCG@5 floor.
3. **Post-retrieval gate (FrugalGPT-style)**: if top normalized hit score < θ_low (per-corpus calibrated; start = 25th pct of historically clicked queries) or zero hits above noise floor → escalate to next corpus; after exhausting corpora → escalate retrieval tier (lexical → dense → graph multi-hop). SymRAG (arXiv 2506.12981) validates complexity/load-aware gating.
4. **Memory guard**: before loading any ONNX/torch encoder, check MemAvailable ≥ 3072 MiB; degrade to lexical-only routing under pressure.
5. **UX affordances**: show ranked plan before searching (`Plan: core-api → worker → docs`), stream per-corpus results as they land deduped by canonical ID, explicit `repo:`/chip overrides (user hint > classifier > default, GitHub code-search convention), always surface "searched X: 0 hits" for trust, log every routing decision for later SetFit distillation.

## Verdict
Top pick: two-tier classifier-lite router — entity-gazetteer (L0) + potion-base-8M centroid cosine margins (L1, ~30 MB MIT model, sub-ms) over SQLite FTS5 probes, gated by FrugalGPT-style θ_low escalation and ReDDE size priors; fully offline, no GPU, far under the 3 GiB memory floor.
Integration sketch: build df-tables + per-corpus centroids during the running deterministic-ID index rebuild; decision fn = weighted sum → margin rule δ≈0.12 (calibrate à la RouteLLM); parallel top-2 fan-out on 16 cores; log every decision to later distill into SetFit once labels exist.
Skip-for-now: Haystack wiring (we already have a pipeline layer) and torch-based routers until label volume justifies them.
