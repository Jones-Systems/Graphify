## Which signals an agent harness can log (proposed schema)

Append-only SQLite (`events`, `queries`, nightly-materialized `judgments`); every search persists an immutable **impression snapshot** (doc_id, rank, bm25/dense/ppr/rrf/reranker scores) — this is non-negotiable, it enables propensities, negatives, and replay eval later.

|Event|Semantics|Judgment contribution (labels 0–3)|
|---|---|---|
|search.query|text, ts, session_id, prev_query_id|groups the training rows; feeds reformulation_index|
|impression|candidate set with rank+scores|label 0 baseline; enables p̂(position)|
|open_from_results|file opened from result list|dwell>60s or ≥3 lines viewed -> 2; open<5s then abandon -> 1|
|edit_after_open|edit within 300s of opening from results|**3** (strongest positive)|
|copy_from_result|clipboard from snippet|**3**|
|accept_suggestion / reject_suggestion|applied vs discarded suggestion|3 / 0|
|reformulate|next query in chain (shared token or ≤120s gap)|no action on prior set => soft-negative for skipped top-3 (weight −0.3, not hard 0)|
|abandonment|impression set, zero downstream events|all candidates stay 0 (implicit negative via pairwise loss)|

Position is logged on EVERY interaction — it powers IPW (#5/#6). Effort: one emitter module + WAL-mode sqlite; ~50 LOC in the harness, zero runtime deps.

## Feature design (~35 cheap features)
- **Retrieval agreement:** bm25_score; dense_cosine (arctic-embed-m-v1.5); ppr_score (graphifyy); rrf_rank ×3; bge_reranker_base score; pairwise score margins between adjacent ranks; rank-disagreement indicators (bm25-top vs vector-top).
- **Doc statics (precomputed at index time):** git_recency_days (log1p), commits_30d, author_count, loc_bucket, path_depth, ext_class (source/test/doc/config), is_test, currently_open_buffer (live editor state), import-adjacent-to-hot-file (graph edge to recently-edited node).
- **Query-side:** token_count, idf_mass, has_identifier_token, reformulation_index, session_query_count, seconds_since_prev_query, hour_of_day (weak, optional).
- **Usage-derived (nightly refresh):** time-decayed smoothed CTR per doc and per path-prefix (α=5 prior, half-life 30d); accept_rate per suggestion type; per-repo normalization stats.

## Small-scale CPU feasibility

- **Data reality (single-user agent fleet, 18 repos):** ~50–300 sessions/day ⇒ after 4–6 weeks ≈ 5–15k impressions, 500–2k engaged positives across hundreds–thousands of query groups. [INFERENCE from typical interactive-session rates]
- **Compute:** LightGBM histogram GBDT on ≤50k rows × ~40 features trains in SECONDS on a few cores; resident RAM tens of MB — nowhere near the 3072 MiB floor even co-resident with embedding jobs. [INFERENCE from histogram-binning memory profile; LETOR-class examples in-repo train interactively]
- **Recipe:** `objective="rank_xendcg", metric="ndcg", eval_at=[1,3,5,10], learning_rate=0.05, num_leaves=31, min_data_in_leaf=20, feature_fraction=0.8`; default `label_gain` (0,1,3,7) matches graded labels; `lgb.early_stopping(50)`; IPW row weights 1/p̂(rank). **Time-split validation only** (train < date < valid) — random splits leak session context.
- **Staged rollout ladder:** Stage 0 (week 0): log everything, no behavior change. Stage 1 (week ~2): Bayesian priors into gated RRF, λ≤0.25. Stage 2 (month ~2, ≥~300 judged groups): train GBDT head; run in shadow (log-only scoring), check replay NDCG@10 vs incumbent, then team-draft-interleave live; promote on significant win-rate, λ stepped 0.25→0.5. Static bge-reranker ordering remains the permanent fallback on low-confidence groups (thin history ⇒ shrink to prior).
- **Failure modes & guards:** position bias ⇒ IPW + tail ε-randomization; sparse positives ⇒ listwise loss tolerates it, but never train on <100 groups; feedback-loop drift ⇒ cap λ, nightly retrain, keep interleaving canary running; single-agent selection bias ⇒ expect narrow generalization, treat head as per-workstation personalization, not universal relevance.

## Verdict
Top pick: **LightGBM 4.7.0 `rank_xendcg` head trained nightly on a local SQLite impression+interaction log with IPW and time-split eval** — MIT, CPU-trivial at our volume, meets every hard constraint, no owner approval needed. Integration: emit impressions/actions from the harness now (one emitter module), ship Bayesian-smoothed priors into the existing gated 3-way RRF immediately (λ≤0.25), and promote the GBDT head only after team-draft-interleaved win-rate beats the static bge-reranker ordering. Steal Metarank's event/judgment schema; deploy none of the services.
