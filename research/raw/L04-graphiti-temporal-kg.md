# L04 — Graphiti (Zep) Temporal Knowledge Graph — Full-Local Feasibility

**Lane:** T1 graphrag · **Date of evidence:** 2026-08-25 · **Investigator:** L04
**Questions:** (1) full-local run without Zep cloud, (2) graph-DB dependency reality (Neo4j/Falkor), (3) what the temporal-edge model adds for repo content, (4) maintenance burden.
**Environment constraints applied:** Debian VPS · 16 cores / NO GPU · 64 GB RAM with MemAvailable ≥ 3072 MiB floor during bursts · Python 3.13 · offline/self-hostable · permissive licenses preferred · no cloud API keys without owner flag.

## Direct answers

**1. Full-local without Zep cloud: YES, confirmed feasible — but only via `graphiti-core` directly.** Graphiti is bring-your-own-graph-DB; Zep Cloud is a separate managed product and is never required. Upstream documents local servers (Ollama, vLLM, llama.cpp, LM Studio) through `OpenAIGenericClient` with a placeholder API key and `base_url=http://localhost:11434/v1`. Gotchas verified from docs/README: use `OpenAIGenericClient`, NOT `OpenAIClient` (the latter hits OpenAI's `/v1/responses` → 404 on Ollama); set `embedding_dim=768` for nomic-embed-text and never reuse an index built with another dim; upstream's own example uses `deepseek-r1:7b` yet warns small models frequently emit schema-invalid JSON → extraction failures; disable opt-out PostHog telemetry (`GRAPHITI_TELEMETRY_ENABLED=false`) for offline compliance. The FastAPI server and MCP server layers are more OpenAI-centric (local-model support tracked in issue #1226).

**2. Graph DB dependency: mandatory, one of Neo4j 5.26 / FalkorDB ≥1.1.2 / Amazon Neptune+OpenSearch / Kuzu 0.11.2.** Kuzu is deprecated upstream (project unmaintained) — avoid; Neptune/Aura are cloud — excluded. For us: **FalkorDBLite embedded** (`graphiti-core[falkordblite]`, requires Python ≥3.12) spawns an embedded Redis+FalkorDB child process from Python with file-backed persistence and zero config/Docker — best fit for our low-RAM, no-daemon preference. FalkorDB standalone container is the middle option; Neo4j Community (JVM service, heap tuning) is the heaviest and least necessary at our scale.

**3. What the temporal-edge model adds for repo content: real but conditional value.** Every fact edge carries `valid_at`/`invalid_at`/`expired_at` plus system-time fields; when a new episode contradicts an existing edge, the old edge is auto-invalidated (not deleted), preserving full history, and every entity/edge traces to source episodes (provenance). For single-snapshot ingestion of our 18 static repos this machinery is pure overhead — all facts share one reference time. It pays off only if we ingest git history as ordered episodes (reference_time = commit date), enabling graph-as-of-commit queries ("which modules imported X before refactor Y") and automatic supersession of stale facts as repos evolve. Benchmark evidence (arXiv 2501.13956, Jan 2025) is conversation-memory-domain (DMR 94.8% vs MemGPT 93.4%; LongMemEval up to +18.5% accuracy, −90% latency) — transfer to repo search unproven.

**4. Maintenance burden: HIGH for the pipeline, LOW-MEDIUM for storage if embedded.** (a) Churn: ~60 PyPI releases Apr 2025→Aug 2026 (0.10.x→0.29.3), still pre-1.0; constructor API changed at v0.17.0 (driver-based); Kuzu driver added then deprecated mid-stream; MCP server versioned separately (mcp-v1.0.2). (b) Dependency hygiene incidents: unpinned redis resolving 8.1.0 breaks FalkorDriver construction (#1756, pin redis<8); FalkorDB group_id regression in 0.18.x on Python 3.13 (#841); Kuzu C-extension access violations on py3.13 (#1469). (c) Ingestion economics dominate: per episode ≈ 2 + R + A + C + ⌈N/30⌉ LLM calls where R≈edges needing duplicate/contradiction resolution; measured community reports: ~160 calls for a 5 KB doc (#1516), 100 records ≈ 1 hour on v0.28.1 (#1262). On our CPU-only box (local 7–14B model, effective concurrency ≈1–2) ingesting even one repo = thousands of sequential LLM calls = days; 18 repos impractical. (d) Known scale defect: node-resolution prompt grows O(n) with graph size → max_tokens failures (#1275). (e) Ops surface choice sets steady-state burden: falkordblite ≈ none; standalone FalkorDB low; Neo4j JVM medium.

## Verdict (≤3 lines)

**Top pick: none adopted now.** Full-local Graphiti IS feasible without Zep cloud (falkordblite embedded + Ollama + telemetry off, all Apache/BSD-wrapped except SSPL server binaries), but CPU-only ingestion economics (~6–134 LLM calls/episode; #1516: ~160 calls per 5 KB doc; #1262: 100 recs ≈ 1 h), pre-1.0 churn (~60 releases/16 mo, Kuzu deprecated mid-stream, redis-8 breakage #1756), and zero benefit for static snapshots make it do-not-adopt-today; temporal payoff exists only for git-history-as-episodes.
**Why:** our pinned graphifyy==0.9.16 structural layer already covers link-graphs; Graphiti's unique adds (bi-temporal validity, provenance, hybrid BM25+vector retrieval) all require an LLM extraction pipeline we cannot afford locally and may not key without owner approval.
**Integration sketch if revisited:** pilot ONE repo pinned `graphiti-core==0.29.x[falkordblite,sentence-transformers,gliner2]` + Ollama qwen2.5:14b (edge resolution only; GLiNER2-small for CPU entity NER; nomic-embed-text dim 768; BGE reranker; GRAPHITI_TELEMETRY_ENABLED=false; SEMAPHORE_LIMIT=2), instrument generate_response() call counts + MemAvailable floor before any scale-up; alternatively steal the bi-temporal edge schema (valid_at/invalid_at/expired_at) into our NetworkX JSON at near-zero cost.
