**Verdict (top pick + integration sketch):** Top pick is a 3-tier router assembled from Drain3 + pyahocorasick/FlashText + semantic-router, emitting templated tantivy query strings — no generative LLM anywhere, all MIT/BSD, all CPU-only, RAM well under the 3 GiB floor. Integration: mine approved genuine user-prompt text with Drain3 (mask paths/symbols/numbers) → promote top clusters into (a) literal keyword tier via pickled ahocorasick automaton, (b) paraphrase tier via semantic-router over utterance exemplars with the existing embedder and optimized thresholds, (c) each route maps its extracted slots into a tantivy boolean query; unmatched input abstains into the current BM25+vector+PPR fusion unchanged. Skip Quepy entirely.

## Hit-rate expectations (honest assessment)

**Data-hygiene constraint:** Mining must use an approved prompt corpus, filter to genuine user prompts, and strip harness scaffolding and machine-templated directives before clustering. The principal acceptance criterion is honest abstention and routing accuracy; no private-sample traffic or recall estimate is retained.

**External calibration:** Affolter, Stockinger & Bernstein, VLDB Journal 28:793–819 (2019), report that keyword and trigger systems handle simpler queries but struggle with nested structure, and caution that evaluation protocols are not directly comparable. Spider 2.0 illustrates the difficulty of enterprise text-to-SQL even for neural systems. The fastText bag-of-tricks study supports CPU-trained linear classifiers, but target precision and coverage require a dedicated labelled evaluation set.

**Closed loop:** measure per-route precision, recall, and abstention on an approved evaluation corpus; review unmatched retrieval-shaped prompts as later template candidates.
