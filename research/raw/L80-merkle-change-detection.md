**Verdict.** Top pick: rows 1+2 combined — keep the flat SHA-256 manifest as source of truth and add a thin fixed-fanout Merkle layer computed from its rows, because on small diffs the tree saves nothing locally (update cost is dominated by the O(N) stat walk both approaches share; the tree adds only ~4 micro-hashes per changed path) while a single root digest gives us a cache-key/version token, Cassandra-style subtree-skip diffing of two staging views, and O(log N) proofs for ENG-C13 verification gates.
Integration sketch: extend the ENG-C11 fingerprint pipeline — leaves stay exactly the sorted canonical inventory rows (path/resolved/type/size/SHA-256; no timestamps/inodes), internal nodes = BLAKE3(or SHA-256) over length-prefixed f=32 child digests, serialized tree written atomically next to `corpora.manifest`, and the root digest feeds the existing `staging checksum` slot so the valid\|stale\|unknown contract is untouched; wire watchdog events to the stat-prefilter rescan, keep a scheduled full-rehash pass (Cassandra's documented reason: incremental-only never rediscovers silent corruption), and reach for Bao/fastcdc only when federation or big blobs materialize.
Cost anchors (derived): 500 MB corpus ≈ 0.25–0.5 s SHA-256 full rebuild warm-cache (SHA-NI-class throughput); N=20k stat walk ≈ 0.1–0.5 s CPython; small diff D=10 → both designs re-hash only those bytes plus negligible metadata.
