# L34 — T5 code-graphs: Reusing LSP data we already generate (SCIP/LSIF protobuf captures → graphify-compatible cross-file symbol/reference edges)

Date: 2026-08-25 · Lane: L34 · Constraints honored: Debian VPS, 16c CPU-only, MemAvailable ≥3072 MiB floor, Python 3.13, offline/permissive-only unless flagged.

**Core answer: YES.** SCIP captures (protobuf) contain exactly the data needed for cross-file symbol/reference edges: `Document.relative_path` + `Occurrence{range, symbol, symbol_roles}` + `SymbolInformation.relationships` (implements/type-definition) keyed by globally unique symbol strings (scip.proto, github.com/scip-code/scip, checked 2026-08-25). Grouping occurrences by symbol across documents yields def-node ↔ ref-edge pairs mechanically; def-doc ≠ ref-doc ⇒ cross-file edge by construction. Conversion into graphifyy-compatible input is a small pure-Python job because our ingest contract is plain NetworkX node-link JSON (`{"directed", nodes:[{id, source_file…}], links:[{source,target}]}` — confirmed in `tools/graphify/offline_extract.py`, which emits `json_graph.node_link_data(G, edges="links")`, and `tools/graphify/validate.py`, which enforces unique ids, resolvable link-source endpoints, root-contained `source_file`, and classifies unresolved targets as `external_bare_import`/`conservative_internal_looking` warnings). No standardized Microsoft "LSP session capture format" exists (LSP 3.18 spec has none; checked 2026-08-25), so the two viable reuse paths are (a) batch SCIP indexes from running-indexer binaries and (b) live JSON-RPC recording via lsp-devtools.

**Verdict:** Top pick = rust-analyzer native `rust-analyzer scip .` (+ scip-typescript / pinned pyright-scip for other languages) → `scip print --json` → a ~200-line stdlib-Python converter joining `Occurrence.symbol` across `Document`s into graphify node-link JSON that passes `validate.py` unchanged (nodes = unique symbols + defining files with root-relative `source_file`; links = ref→def with `kind` tag; unresolved targets dropped into the existing `external_bare_import` warning class so ENG-C7/C8 ceilings govern adoption). Why: zero new runtime deps beyond one hash-pinned static binary, CPU-only, RAM Δ tens-of-MB at ~28k-node corpus scale, and it converts today's biggest quality gap (per-file AST extraction with heuristic import links) into compiler-grade cross-file edges feeding PPR-over-KG.
