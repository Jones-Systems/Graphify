## Verdict
Top pick: **multi-pass union blocking (exact token-sort keys + capped trigram inverted index + one SNM pass w=10 + optional metaphone key) verified by `process.cpdist`(JaroWinkler.normalized_similarity, score_cutoff≈0.85, workers=-1, dtype=uint8)** — recall-first per survey doctrine, all inside the existing pinned dep plus one tiny MIT addition (jellyfish==1.2.1).
Why: full pairwise @200k = 2×10¹⁰ pairs (uint8 dense = 40 GB, float32 = 160 GB — impossible); blocking shrinks to ~1-10M candidates → seconds-minutes on 16 CPU cores, RAM far under the 3 GiB MemAvailable floor.
Sketch: build `dict[key]->list[idx]` blocks → cap blocks >500 → collect dedup'd (i,j) int32 arrays → one `cpdist` call over all pairs (GIL-free, multicore) → union-find clusters → canonical entity nodes feeding graph.json and downstream PPR-over-KG fusion. Verify exact rapidfuzz constraint via `importlib.metadata.requires("graphifyy")` at implementation time.

**Scale math**: C(200k,2)=1.99999×10¹⁰ brute pairs. Blocked estimate: 200k nodes × ~15-60 unique trigrams → inverted index ~2-6M postings (≤~500 MB dict worst case; use sorted int arrays to cut ~5×); candidate pairs ~10⁶-10⁷ → pair arrays ~8-80 MB. Verification throughput [INFERENCE]: 10-50M cmp/s/core for short strings (GIL released per official docs; no independent benchmark located this lane) → even 10⁷ pairs < ~1 min on 16 cores.

**Evidence dates**: rapidfuzz 3.14.5 (2026-04-07); jellyfish 1.2.1 (2025-10-11); DoubleMetaphone 1.2 (2025-05-11); Splink 4.0.16 (2026-03-11); recordlinkage 0.16 (2023-07-20); Pass-Join PVLDB 2012; survey arXiv:1905.06167; local pin evidence read 2026-08-25 (`docs/plans/graphify-v3-setup/work-note.md`, `tools/graphify/install.sh`).
