**Ops-weight reality check (VPS: Debian 13, 16 cores, no GPU, 64 GB RAM, MemAvailable floor 3072 MiB)**

1. Build pain is the dominant cost, confirmed by Glean's own lead: Simon Marlow, 2025-05-22 (simonmar.github.io/posts/2025-05-22-Glean-Haskell.html): Glean is "not the easiest thing in the world to build"; troublesome deps are Folly and RocksDB; distro packages generally too old; source build = system packages + `install_deps.sh` (builds hsthrift+folly+rocksdb from source) + env vars + make. GHC/folly compiles can burst well past the 3 GiB MemAvailable floor unless parallelism is capped or built off-box.
2. Official Docker image is declared broken on the current docs page ("The Docker image is currently not working"); the ghcr.io demo image is ~7 GB with a stale React/Flow DB dated 2021-05-24. Third-party image (hub.docker.com/r/dgellow/glean) needed pinned GHC/GCC, Folly patches, retries, and dropped glean-lsp — reproducible containerization is nontrivial.
3. Runtime itself is modest once built: demo React+Flow DB totals 17.57 MB of facts; LMDB experimental backend is 30–40% faster than RocksDB per CHANGELOG. Indexing 18 repos is trivially small by Glean standards; storage/RAM at query time is not the blocker — toolchain ops is.
4. Coverage mismatch: our repos' languages get no native OSS indexer beyond Python (Pyre-based) — everything else routes through third-party SCIP/LSIF generators anyway, i.e., we'd operate a Haskell/Thrift/RocksDB service to import indexes we could ingest directly into our own KG.
5. Integration friction: no Python query client; Angle results reach our tantivy/LanceDB fusion only via Thrift codegen or subprocess scraping of `glean shell`.

**Verdict:** Top pick = row 6 (skip Glean; ingest SCIP facts into the existing graphifyy KG). Glean OSS is genuinely alive (pushed 2026-08-25, BSD-3) and its fact quality is excellent, but outside Meta you inherit a Linux-only GHC 9.6.7 + hsthrift + Folly + RocksDB source build, a broken official image, single-node-only indexing, and no Python client — pure ops weight for facts obtainable via MIT-licensed SCIP indexers. Integration sketch if ever revisited: run `glean-server` (+LMDB) in a dedicated container built once off-VPS, expose Thrift, write a thin Python Thrift client mapping Glass-style symbol/xref facts into the code-KG used by PPR fusion; do not attempt on-VPS source builds under the 3 GiB floor.
