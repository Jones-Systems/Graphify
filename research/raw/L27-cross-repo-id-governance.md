## Ground truth being generalized (read in-repo 2026-08-25)
- Spine split follows identifier lifecycle: bioguide = person/served layer (100% current + 12,231 historical coverage); FEC candidate id = candidacy/running layer (only at-scale challenger identifier; legitimately multi-valued per person — Ossoff holds H8GA06195 AND S8GA00180); OCD-person UUID = state layer (no external crosswalk exists).
- `core.politician_identifier` is an APPEND-ONLY typed assertion log: politician_id FK, namespace FK (17 seeded namespaces w/ usable_as_join_key flag), value, confidence ladder CHECK ('verified','matched','reviewed','retracted'), artifact_ref (finer pin: YAML commit SHA / cn26 pull date / Wikidata dump ts), source_document_id (sha256 receipt), transform_run_id, first_seen, last_verified, supersedes_id self-FK, retracted_at, retract_reason. Correction = new superseding row or retraction set; NEVER UPDATE in place.
- Uniqueness enforced among LIVE rows only: partial unique index uq(namespace,value) WHERE retracted_at IS NULL + one-live-bioguide-per-person partial index. Collisions route to core.identity_match_proposal review queue (kinds live in a lookup table so donor/state reviews join without DDL); never overwrite.
- Update protocol: nightly YAML loader pinned to commit SHA; abort-and-alert on no-op day or member-count drop >5 (prune detection, friction T04); challenger-wins promotion flow auto-proposes merge running->served carrying all assertions over; FEC id stays alias forever; merges never delete (superseded_by edge + permanent URL 301s); disagreement precedence government-issued > Wikidata > aggregator wikis, conflicts open review rows instead of flipping silently; weekly N=25 stratified spot-check re-fetches origins.
- Coverage reality encoded as nullability/flags, not assumption (ICPSR usable_as_join_key=false at 319/537).

## Generalization checklist for the 18 repos (port of Compass design)
1. Minimum xref schema per repo joining external ids: entity(id PK) + entity_identifier(entity_id FK, namespace FK lookup w/ usable_as_join_key flag, value, confidence ladder, artifact_ref, source_document_id, transform_run_id, first_seen, last_verified, supersedes_id, retracted_at, retract_reason) + match_proposal(kind FK lookup, score, decided_by, decided_at, evidence jsonb). Append-only; two partial unique indexes (live namespace/value uniqueness + spine-namespace one-per-entity).
2. Provenance column minimums (from OpenSanctions statements model): every assertion carries WHO/WHAT asserted it (dataset/source doc hash), observation interval first_seen/last_verified (distinct from real-world event dates), origin class (crawled/inferred/manual), and original_value when normalization touched it. Canonical ids treated as mutable: downstream rows freeze the id they consumed at creation time.
3. Conflict classes -> handlers (port of Compass §11): multi-id-same-person = append aliases; confusable-name twins = gates + review queue; upstream correction = follow next diff, log, retract locally pointing at successor assertion; community-source vandalism/disappearance = flag source for refresh, never retract a verified assertion; false merge discovered later = split creating new entity moving exactly named assertions + audit entry + cache invalidation. Merges never delete: survivor keeps union, absorbed gets superseded_by, URLs redirect permanently.
4. Update protocol when upstream ids change: nightly pinned-source diff -> classify {append, correction, retraction, prune} -> auto-append safe classes -> ambiguous to kind-typed queue -> prune/format tripwires halt loader + alert -> weekly N=25 stratified spot-check re-fetch -> coverage dashboard with per-namespace fill-rate regression alerts (>2/day). Disagreement precedence published once (government-issued > community-curated > aggregator wiki).

## Verdict
Top pick: extract Compass's append-only assertion-table pattern into a tiny shared id-xref package (PG DDL + loader helpers + review-queue CLI) adopted by all 18 repos — highest combined gains at adoptCost 1 and already proven end-to-end by the Ossoff practice run. Why: every other candidate implements one slice of it (nomenklatura = adjudication state machine, Splink = gray-band scorer, PG partial indexes = enforcement, FEC/YAML/Wikidata contracts = feeder semantics), so standardizing the core makes each add-on pluggable. Integration sketch: repos ship loaders that pin upstream SHAs with prune tripwires and write assertions only; consumers resolve (namespace,value) against live rows exclusively; corrections insert supersedes rows; precedence policy and confidence ladder defined once in the shared package, reviewed decisions immutable across all repos.
